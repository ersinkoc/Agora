**#555 (#545: write entries followed through links), independent review (Linux: fmt, clippy -D warnings incl. aarch64-apple-darwin for agora-platform, tests green; head 6d55838): CHANGES NEEDED. The idea is right and a swap AFTER the profile is built is safe (the profile names the `canonicalize`d path and Seatbelt checks the real path at access time). Findings:**
1. **HIGH — check-then-use race.** `through_agents_link` checks every entry, `canonicalize` runs later: two separate syscalls. Another confined agent with the same write entry (every Claude agent writes `~/.claude`) or a leftover background process can flip `~/.claude` between a real folder and `ln -s ~`; if the check sees the folder and `canonicalize` sees the link, the profile gets `(subpath "$HOME")` — and the restart policy gives the attacker repeated tries. Prove on the Mac: as a confined agent `while :; do rm -rf ~/.claude; ln -s ~ ~/.claude; rm ~/.claude; mkdir ~/.claude; done &`, start a second agent in a loop and grep its profile for `subpath "$HOME"`. **Fix:** walk each entry one component at a time, opening each with `O_NOFOLLOW` (`openat`) and refusing links inside write entries, then emit `fcntl(F_GETPATH)` of the final descriptor: check and resolve become one step.
2. **MEDIUM — the match is on spelling, not on the real place.** `c.starts_with(w)` compares paths as written: a link the agent makes under `/private/tmp/...`, `/System/Volumes/Data/Users/...` or another upper/lower-case spelling slips past write entries spelled `/tmp` or `~/.claude` (the owner's `sandbox.write/read` and manifest `needs` need not use the node's spellings). Compare against the RESOLVED write entries with the same component walk as in 1.
3. **MEDIUM — the advice to the user is unsafe.** en/tr say "List the place the link points to instead" and error-codes.md "list the link's target instead": in the attack case that tells the user to add `~/.zshrc` (or `~`) to `sandbox.write`. Reword: the agent may have made this link; check it and remove it if you did not make it. Also error-codes.md says "not owned by root" but the code checks `access(W_OK)`, not ownership.
4. LOW (by design, say it in the docs): a GNU-stow style `~/.claude -> ~/dotfiles/claude` is now refused (the write entry itself is a link in a writable `~`); it cannot be told apart statelessly from one the agent made.
5. **Same class, outside this PR — please measure and file an issue if it prints pwned:** hard links. `mkdir -p /tmp/h/w; echo rc >/tmp/h/zshrc; sandbox-exec -p '(version 1)(allow default)(deny file-write*)(allow file-write* (subpath "/private/tmp/h/w"))' /bin/sh -c 'ln /tmp/h/zshrc /tmp/h/w/x && echo pwned >>/tmp/h/w/x'; cat /tmp/h/zshrc`. If it prints `pwned`, file write entries need an `st_nlink == 1` check at profile build (and the worktree itself must not hold hard links to files outside).
Only a Mac can confirm: whether the race in 1 can be won in practice, 5, and whether Seatbelt applies `subpath` to firmlink spellings. Post the new head; short re-check, then merge.
