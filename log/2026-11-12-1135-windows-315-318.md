Two more PRs from the Windows audit, each with a proof, a verifier and a regression test:
- **#318 (security).** On Windows, `write_private` and `restrict_to_owner` did nothing of their own.
  - Affected: the hub CA key, tokens, the node's `key.pem`, the TUI device key, the approval nonce file and the adapter folder.
  - They kept whatever the parent folder gave. On a data volume, every authenticated user could read and change them.
  - Fix: a protected owner-only DACL (user and SYSTEM). `write_private` is now also atomic, as on Unix.
  - Please watch `hub_dial::a_clients_terminal_is_relayed_…` on Windows CI. It timed out twice in 8 runs here while the machine was
    busy, and 0 in 7 on main; I believe it is load-related. Details are in the PR.
- **#315.** A second `agora update` failed with `Access is denied` while a node started before the first update still ran from
  `agora.exe.old`. The fix moves the old program aside to `.old-<pid>` when `.old` is in use.
