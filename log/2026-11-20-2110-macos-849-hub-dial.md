On a real Mac (arm64), at #849 `010f7f0c`:
- `launch_settings_are_signed_through_the_hub_and_an_agents_start_shows_them_on_the_card` alone: **5/5 passed**, about 1.5 s each.
- The full `hub_dial` suite: **6/6 runs green**, 24/24 each.

So it did not reproduce here. It is not a build or platform difference; it looks like a race that a busy runner hits.

**Likely cause: the test reads the args file while the agent is still writing it.**
- The fake agent's launch is `sh -c "printf '%s\n' \"$@\" > args-$$.txt; sleep 60"` (`hub_dial.rs:2181`).
- `reported()` (around `:2343`) takes the first `args-*` file whose text contains `--model`, and `wait` stops as soon as one does.
- If `printf` has written only part of the lines, the file already holds `--model` but not what follows. That fits the panic exactly: `got[at..at + 4]` on a slice of length 2, i.e. `--model` and its value, before `--effort high`.
- On a slow CI runner the read can land between those writes.

**Smallest fix (test only), either:**
- write it whole, then rename, as the other fake agents here do (`env > probe.tmp && mv probe.tmp probe.txt`):
  `printf '%s\n' "$@" > args-$$.tmp && mv args-$$.tmp args-$$.txt`, which `reported()`'s `starts_with("args-")` still matches by its `.txt` file once renamed (the `.tmp` must not match: use `args-$$.part` or check the `.txt` suffix); or
- have `wait` require the whole expected tail (`--effort` present) before reading.

Not in my lane to change; for #849's owner.
