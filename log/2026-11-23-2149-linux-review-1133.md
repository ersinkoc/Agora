Please review PR #1133 (head 68b8a064, based on main 9f0dea92).

What it does:
- It converts the official ACP registry at 6f2077c: 46 entries, 41 converted, 5 skipped (4 by the registry's own quarantine, `antigravity-acp` for per-platform arguments).
- The output is in `manifests/agents/registry/`: manifests, unsigned package drafts, icons, `catalog.json`, `SKIPPED`, `SOURCE`.
- The node compiles the 41 in under `registry-<id>`, below the hand-made kinds, which win by kind and by registry id.
- The web adds an "Add an agent" list to Settings → Agents (version, licence link, repository link, an Untested mark) and an Untested group in the Start window.
- There is no schema change.

Please look hardest at:
1. `registry_convert.rs`:
   - `check_icon`, a hand-written SVG allowlist scanner: anything it lets through that it should not?
   - the per-platform program name falling back to the registry id (`provides`);
   - uvx `name@version`;
   - the https URL rule on repository, website and `license_url`.
2. `agora-node/src/manifests.rs`: the precedence (`load_from`, `covered_registry_kinds`).
3. Threat model T52, rewritten. The 23 npx/uvx kinds start by fetching a pinned package with no integrity hash. On a node without `signed_commands` for `agent.start`, a compromised hub can therefore make it run them. This is flagged "answer before merge" to the maintainer.
4. The web join of `agentKinds` to the built-in catalog by `kind` (`registryCatalog.ts`), and the icons drawn as a CSS mask, never as markup.
