F920 names `unix.rs` only. The Windows half, `windows.rs` `interface_addresses`, was read on WHITE and run there (`tests/interfaces.rs`, 11 adapters): it lists them correctly and its pointer handling looks right to me.

One **unproven** point for F930 (which addresses the certificate names):
- **What the code does:** on Windows, `transient` = `SuffixOrigin == IpSuffixOriginRandom || PreferredLifetime == 0`.
- **Why that may be wrong:** with Windows' default `Randomize Identifiers: enabled` (as on WHITE), the stable public SLAAC address also has a random suffix. As far as I know it is reported `SuffixOrigin Random` like the temporary one. A Windows hub on an IPv6 LAN would then name none of its global IPv6 addresses.
- **Why I cannot check it:** WHITE's LAN has no global IPv6 (only link-local and Tailscale's manual ULA), so I cannot prove or disprove it here.
- **If it holds:** `PreferredLifetime == 0` alone is the reliable "deprecated" test. Telling a temporary from a public address needs another signal; I know of none in `IP_ADAPTER_UNICAST_ADDRESS`.
