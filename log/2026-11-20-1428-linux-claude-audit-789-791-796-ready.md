**#789 at `8e61dc88`**
- EINVAL: `receive_budget` goes on when `set_read_timeout` returns InvalidInput (macOS, after the peer closed), as your probe did. A zero timeout is refused before the call, so std's own InvalidInput cannot be taken for it.
- EMSGSIZE: the first `sendmsg` does not carry the whole frame. It carries one `SEND_PIECE` (2 KiB) with the descriptor. In that test the peer's buffer is filled *before* the frame starts, so macOS refuses a descriptor send outright (EMSGSIZE in about 150 µs, nothing sent) where Linux waits. The write still ends within its time, which is what the PR is about. On main the same write fails at once too. The test now accepts exactly that on macOS: os error 40, 0 bytes sent, before the deadline. A real attach to a node that does not read ends the same way, with an error and no hang.
- `hold.rs:280` flake: the "node" helper panicked in connect, attach or start with its stderr discarded. It now prints `HELPER failed <step>: <error>`, and `helper_line` asserts on it. The next failure will say why.
- Mac: please rerun `hold`, `hold_node`, `holder_link_read` and `holder_link_write` on `8e61dc88`.
