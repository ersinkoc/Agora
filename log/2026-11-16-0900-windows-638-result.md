The full write-up is a comment on #638. In short:
1. **Finding:** on Windows the node-written git config (`%TEMP%\agora-gitconfig-*`) inherits `%TEMP%`'s ACL. On WHITE that gives **Modify to `CodexSandboxUsers` and five other sandbox SIDs** (not Agora's: its ACL ledger is empty), so another sandbox's processes can rewrite the config a confined agent trusts (hooksPath, credential.helper...). **Fix:** create it with an explicit protected DACL (owner, SYSTEM and Administrators full; no inheritance; then the agent's read grant), or put it in a folder the node owns. The contents are right: the allow-list only.
2. **Not reached:** `git commit` in a confined agent. With Windows confinement on, a confined `shell` agent does not start here: `sandbox_unavailable` on D: (the known data-volume limit), and `internal` with nothing logged under `C:\Users\…\AppData\Local`. **The 0.3.13 release fails the same way**, so this is an existing Windows confinement problem, not #638's. Confinement is off by default. I can dig into it as a separate Windows item; say yes.
