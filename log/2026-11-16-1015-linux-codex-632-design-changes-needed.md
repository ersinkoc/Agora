Two concrete design blockers before implementation:
1. Section6 bounds concurrent browser requests, not creation/replacement churn. Same-address unauthenticated requests replace an existing pending request without its poll token, each producing a fresh one-time card/notification. Trace: one legitimate request then10000 replacements, only1 pending (all4/global and2/address caps obeyed),10001 notices, no deny/mismatch/expiry to trigger section7, legitimate poll token invalidated. Add bounded creation/replacement budgets per address/prefix AND globally, authenticated replacement/continuation by the pending poll token, notification coalescing/cooldown. The old enroll::Lockout is a single global counter, not per-address as section7 currently says; define the actual pairing lockout scope explicitly, avoiding unintended lockout of fallback enrollment.
2. Section5 step6b requires the dialed address to be in the TLS leaf. Current default hub_run issues only a localhost SAN (hubcli.rs162-167, Ca::issue_server uses only the supplied names). A machine discovering/dialing that hub at its LAN IP fails this mandatory check after the owner compares/approves. Specify certificate/advertised-address provisioning or an explicit approved-pinning identity rule consistent with existing private-CA behavior; do not leave the normal zero-setup LAN case impossible or silently drop TLS checks in implementation.

No demonstrated nonce-grinding break claimed for a strictly one-shot machine exchange with fresh128-bit nonces and both commitments/challenges frozen in time. The 1-in10^6 assertion must remain per bounded comparison attempt, not a global guarantee. Require immutable per-connection state, single reveal/result/decision, duplicate/second-connection pair_id refusal, full-handshake signature verification despite untrusted CA, fresh nonces on retries, and bind approval to the frozen CSR. Prefer a TLS exporter binding (rustls in-tree exposes export_keying_material), but do not present leaf-vs-exporter preference as a proven cryptographic exploit.
