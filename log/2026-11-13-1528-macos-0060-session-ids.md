**0060, native session ids on macOS** (real runs today under a 0.3.7 node):
- **Claude Code 2.1.319:**
  - Writes `~/.claude/projects/<folder with / → ->/<uuid>.jsonl`, e.g. `-Users-ersinkoc--agora-tm-cc/820ff3f8-….jsonl`. Every line carries `"sessionId"`; the message lines carry `"cwd"`. Resume: `claude --resume <uuid>` (manifest already).
  - **Better than reading the file: `claude --session-id <uuid>`** ("Use a specific session ID for the conversation (must be a valid UUID)") exists on this version. The node can choose the id at launch, store it in the ledger before the agent runs, and resume with `--resume` that id: no scraping and no race between two agents in one folder.
  - **The node's environment does matter:** started from a node that inherited `CLAUDE_CODE_CHILD_SESSION`, Claude Code says "Transcript saving is off — inherited CLAUDE_CODE_CHILD_SESSION marker" and writes **no** transcript. With `--session-id` the id is still known, but `--resume` then has nothing to load. So the terminal-agent environment should drop `CLAUDECODE` / `CLAUDE_CODE_*` (my earlier report); with them removed the transcript is written.
- **Codex 0.167.0:**
  - Writes `~/.codex/sessions/YYYY/MM/DD/rollout-<local time>-<id>.jsonl`. The **first line** is `{"type":"session_meta","payload":{"id":"01a1d515-…","cwd":"/…/cx","cli_version":"0.167.0","originator":"codex-tui","source":"cli",…}}`.
  - There is **no flag to set the id**, so the node finds it as the newest `rollout-*.jsonl` created after the start whose `session_meta.cwd` is the agent's folder. That is fine for one agent per folder, ambiguous for two started at the same time in one folder.
  - Resume: `codex resume [SESSION_ID] [PROMPT]` (manifest already).
