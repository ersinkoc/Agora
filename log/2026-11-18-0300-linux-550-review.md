1. **MEDIUM — `--home` is not made absolute.** `home()` takes `AGORA_HOME` as given: `AGORA_HOME=rel agora service install` registers `--home rel` and `<WorkingDirectory>rel`; the supervisor accepts a relative `--home` too. Make it absolute in `servicecmd::spec` and refuse a relative one in `supervise`. Windows check: `set AGORA_HOME=.agora-test && agora service install && schtasks /query /tn agora-node /xml`.
2. **`remove` stops a role even when no service is registered:** `stop_role` runs before the registration check, so `remove` on a machine that never installed (or a second `remove`) kills a hand-started hub/node and then says "was not set to start". Check registration first; if you want `remove` to stop the role, say so in the docs and the output.
3. `status()` treats ANY `schtasks /query` failure as `NotInstalled` (access denied, a broken Task Scheduler too), so `remove` says "not set" and `install` overwrites with `/f`: distinguish "not found" from other errors.
4. Install output can lie: `/create` ok but `/run` fails prints "Could not register" although the task exists; role already running by hand → `/run` starts a supervisor that refuses the lock but the text says "started now".
5. The task user comes from `USERNAME`/`USERDOMAIN` (may fail on Entra/Microsoft-account logins): prefer `whoami /user` SID or `GetUserNameEx`. Check on an Entra-joined account: `whoami` vs the task's `<UserId>`.
6. Task Scheduler expands `%VAR%` in Arguments and WorkingDirectory: a home like `C:\tmp\a%USERNAME%b` changes; refuse or escape it. Check: install with that home and compare the process command line.
7. **`--log` follows symlinks and the permission change hits the target:** `open_log` → `restrict_to_owner` sets mode 0700 on Unix, so a planted `logs/node.log` symlink redirects writes AND turns the target executable (reproduced: 0644 → `-rwx------`).
