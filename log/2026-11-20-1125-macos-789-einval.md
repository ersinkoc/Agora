**#789 at `f49094ea` fails on a real Mac (arm64): `cargo test -p agora --test hold` → 11 passed, 4 failed. All four fail with `os error 22` (EINVAL):**
- `a_version_mismatch_changes_nothing`, `hold.rs:493`: "expected a version refusal, got Err(Io(Os { code: 22, … "Invalid argument" }))".
- `a_second_node_connection_is_refused_while_one_is_attached`, `hold.rs:431`: "refused for another reason: holder link: Invalid argument (os error 22)".
- `an_agent_does_not_see_the_holders_own_environment` (`hold.rs:200`) and `a_node_that_keeps_its_terminal_and_drops_only_the_link_reattaches_at_once_and_loses_no_output` (`hold.rs:566`). CI showed only the first two; locally it is four.

**Cause (measured).**
- On macOS, `setsockopt(SO_RCVTIMEO / SO_SNDTIMEO)` on a Unix socket whose peer has already closed returns **EINVAL**, while the data the peer sent before closing can still be read.
- Measured with a socketpair: the peer sends `reply` and closes. Then `SO_RCVTIMEO` → `[Errno 22] Invalid argument`, and `SO_SNDTIMEO` → `[Errno 22] Invalid argument`. `recv` still returns `b"reply"`. With the peer open, the same `setsockopt` is fine. Linux accepts it in both cases, which is why Linux CI is green.
- #789 now sets the read timeout before each receive (`holder_link.rs`: `stream.set_read_timeout(Some(timeout))?` in the per-frame helper) and cuts the write timeout per send (`stream.set_write_timeout(Some(left))?`).
- The holder refuses (version mismatch, busy, …) by writing its `Refused` frame and closing. So the node's `set_read_timeout` fails with EINVAL before it reads that frame, and the `?` turns a clean refusal into `Io(EINVAL)`.

**Smallest fix (suggestion).** In the helpers that set the per-frame timeouts, do not fail on `EINVAL` from `set_read_timeout` / `set_write_timeout` (`ErrorKind::InvalidInput` with raw os error 22):
- Go on to the read. It returns the queued `Refused` frame, then EOF, so the existing paths report a version refusal or `Closed` as before.
- On a write, the following `write` will fail with `EPIPE`, which is already handled.
- Alternatively, set the timeouts once per stream, before anything can make the peer close. Per frame, only shorten them when the call succeeds.
