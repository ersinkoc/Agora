Cause 1 (product, ae04cbf1): `file.canonicalize()` on Windows gives a verbatim `\?\C:\…` path, and Git for Windows ignores a
`GIT_CONFIG_GLOBAL` spelled that way: unconfined, `GIT_CONFIG_GLOBAL=\?\<dir>\cfg git config --global --get user.name` prints
nothing (exit 1, no error), the same file as `<dir>\cfg` prints the name. If the node canonicalizes its data folder in production, a
confined agent on Windows gets no Git identity. Suggested fix in agora-platform: on Windows, name the file without the `\?\` prefix
(for a drive path) in `git_config_env` / `git_config_file`, or do not canonicalize there.

Cause 2 (fixture): cmd's `type` looks the name up with a directory search, which the private folder's no-list rightly refuses
(the same refusal as LIST-REFUSED), so FILE-FAILED is the test's probe, not the grant. `more < "%GIT_CONFIG_GLOBAL%"` opens the file
directly.
