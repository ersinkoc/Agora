Docs only (`docs/specs/pairing.md`), CI green, `check-docs` passes. Per your findings:
1. **Browser admission (§6, §7):** only the holder of a request's poll token may continue, cancel or replace it; a tokenless request from an address whose quota is full is refused (`pair.limit`) and does not touch the pending one. Creation, replacement and poll rates apply to every kind, per address key (IPv4 address, IPv6 /64) and hub-wide, counted before any state is allocated. Notices coalesced to at most one push a minute hub-wide. Your 10,000-replacement trace now gives one pending request, at most 3 admissions a minute from that address and at most one notice a minute. New keyed `PairLimits` table (1024 keys, 10 min retention, refuses new keys when full), separate from `enroll::Lockout`, which stays unchanged.
2. **Default LAN certificate identity (§5b):** the hub provisions the leaf's names at start and at `agora pair open` (the `--name` values, localhost, host name, listening interface addresses), re-issued from the same CA; discovery announces only addresses present in the leaf; if names cannot be provisioned `pair open` refuses; a machine dialling an address not in the leaf gets machine-local `pair.name_unverified` and stores nothing. The name check is never skipped. Acceptance cases: default hub by LAN IP and host name; wrong-CA, wrong-leaf and unnamed-address controls.
3. **Machine exchange:** TLS 1.3 only; the number now includes a TLS exporter (32 bytes, label `EXPORTER-agora-pair-v1`) and the leaf hash; handshake-signature proof of possession kept (only issuer trust is relaxed); new §5a state table freezes owning connection, exporter, leaf hash, commitment, nonces, CSR hash and deadline; `pair_id` honoured only on the owning connection; duplicates/replays get `pair.state`; approve/deny terminal and at most one certificate; poll tokens 256-bit CSPRNG, delivered once, header-only, stored hashed, void on terminal events; browser pairing only over TLS or loopback (`pair.insecure_transport`). The ~1-in-10^6 is stated per comparison; the aggregate bound is about 6x10^-6 per open window (5 failures hub-wide close the switch). Your negative cases are in a new "Tests this design requires" list.
Choices to judge: (a) both exporter and leaf hash bound (cost: TLS 1.3 only on the pairing connection); (b) provision certificate names rather than pin the approved CA (pinning would force a relaxed name check on every later node link, an ADR-0015/0062 matter); (c) the rates, the 5-failure budget and the codes `pair.state`, `pair.insecure_transport`, `pair.name_unverified` are proposals.
