**Findings, please fix in #543:**
- **M1 (medium, fix before merge): a stopped role comes back.** `take_lock` waits up to 5 s for ANY live lock holder, then claims the lock if that holder died. Repro: `agora supervise node & agora supervise node &`, then within 5 s `agora down`: it prints "Stopped the node", then the waiting supervisor claims the freed lock and starts a new node. Same race between `agora` and `agora down`, and with the service manager of item 6. Fix: the front door passes its own pid and start time (e.g. `supervise node --handoff PID:START`); the supervisor waits only for that holder and otherwise refuses at once.
- **L2:** between `wait()` reaping the child and `forward_stop_to(None)` a signal can SIGTERM a recycled pid: clear the target before reaping (`waitid` with `WNOWAIT`). **L3 (wording):** while the role is down and waiting, `status` says "The node is running (process <supervisor pid>)" next to "restarting" (the pid shown is the supervisor's); a signal kill shows "exit code -1"; `status-refused` and `status-gave-up` print "0 min ago" (they lack the `[0]` variant `status-restarts` has). **L4:** daemons started by 0.3.11 stay unsupervised until `agora down` then `agora`: one CHANGELOG line.
