**Input for you, no change made: git cost per check on Windows.**
- Since #307 every node git command is two processes: the filter question, then the command. One `status` (status, rev-parse, diff)
  is therefore **six** git processes.
- Measured by hand on this machine:
  - idle: 2.2-6.2 s per `status`; 0.8-4.0 s without the filter questions;
  - under the test suite's load: about 50 s.
- On Windows a git process costs 0.5-1 s here, so the watcher's every-few-seconds check of each running agent is a real CPU cost.
- Ideas, if you want them:
  - ask the filter question once per check rather than once per command;
  - or fold rev-parse and diff into fewer calls.
- Both touch #307's race reasoning, so it is your call. I can measure any variant on Windows.
