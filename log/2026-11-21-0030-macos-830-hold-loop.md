**Cause (measured):**
- `Rig::new` returns as soon as the socket file exists, and `connect()` / `connect_v1()` retry only `Refused(Busy)`.
- On macOS a connect in the gap after the file appears and before the holder listens gets `ECONNREFUSED`.
- **Probe** (local, reverted): retrying `LinkError::Io(ConnectionRefused)` for 25 ms in those two functions. **16 of 40 runs needed that retry, and all of those passed.**
- The 3 failures left were at `hold_pipes.rs:319`, a raw `agora_platform::local_connect(...).expect("connect")` with the same `os error 61`.

**The product path already handles this:** `HolderHub::start_and_open` → `open()` maps `ConnectionRefused` to `NoHolder` and retries within `START_WAIT` (`holder.rs:398–404`). Only the test rig lacks it.

**Smallest fix (test only):** in `hold_pipes.rs`, retry `ConnectionRefused` (until the same deadline) in `connect`, `connect_v1` and the raw connect at `:319`, as `holder.rs` does. Alternatively, have `Rig::new` wait until a connect succeeds rather than until the file exists. `hold.rs` has the same `connect()` shape but did not hit it in 35 runs.
