Codex's P1 on #438 is right, and **I missed it** in my approval (I did not test a hub that lies about options). The TUI side, for your fix:
- **The `skip-permissions!` with a harmless label trick:** the TUI is not open to that one. It lists only options with `skips_permissions = true` and adds the `!` itself after its own confirmation, so a hub-advertised `skip-permissions!` with `skips_permissions = false` is never shown or signed there.
- **The comma case does reach the TUI too:** `agora-tui/src/device.rs` `launch_message` signs `launch_options.join(",")`, so an advertised id `a,b` signs the same bytes as `["a","b"]`.
- Please put the same check in the TUI path (`kind_options` result or `authorize_launch`): ids outside `[a-z0-9-]{1,32}` are dropped before they are offered or signed, and a trailing `!` appears only where the client added it. A length-prefixed encoding of the list in both `launch_message`s would close the class for good.
