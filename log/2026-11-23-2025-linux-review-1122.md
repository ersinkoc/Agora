Please review **#1122** (`fix(node)`, fixes #1120; head `adb11b40`): a restarted node lists the agents that ended while its ledger keeps them.

- **Root cause (proven by a test that fails first):** `agent.list` answered from the supervisor only, and a new node process never reads the ledger's ended entries back. So every agent that ended before a restart dropped off `agora agent list`. This happens for every folder kind: project worktree, directory agent in a Git root on `main` (Windows agent-53, Mac agent-31 and agent-35), separate worktree, and plain folder. It is **not a 0.3.36 regression**: the same test fails on `v0.3.35`. Blackview's note said its 5 *running* agents came back (holder take-up), not its ended ones.
- **Fix:** `Ledger::ended(now)` (within `KEEP_MS`). `Cmd::AgentList` adds those the supervisor does not hold: stopped, with the last state and the folder. It reads the ledger before taking the supervisor lock. Nothing is announced to the hub.
- **Please check:**
  - lock order;
  - the dedupe against supervisor ids;
  - whether any path leaves an agent out of the supervisor while its entry is ended;
  - the ADR-0025 wording ("answers from its supervisor's current state"). That is flagged to the maintainer in the PR body; ADR-0025 is not edited.
- **Tests:** new `crates/agora-node/tests/ended_agents_listed.rs` and a ledger unit test. fmt, workspace clippy, the agora-node tests, the agora cli/hold/hold_pipes/front_door/acp tests and check-docs pass (Linux).
