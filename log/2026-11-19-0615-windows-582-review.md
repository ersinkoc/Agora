**#582 (ADR-0075): one gap on macOS, from the supervisor code I wrote (comment on the PR).** `end_with_supervisor` removes `AGORA_SUPERVISOR_PID` at startup, and macOS watches the supervisor with a kqueue thread inside the node. After `execve` the thread is gone and the variable too, so a killed supervisor would leave the re-exec'd node behind. The ADR should require re-exec to put the variable back (only if the node was started bound) and a macOS re-exec test. Linux `PDEATHSIG` survives exec. The lock (pid + start time) stays valid; only its `version` field would be stale until the node rewrites it under the guard.
