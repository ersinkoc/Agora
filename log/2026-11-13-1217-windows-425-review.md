**#425 at 24edb59: approve the manifest change.** opencode 2.2.6 accepts opencode acp --print-logs (initialize 2.1 to 5.4 s). The tail question needs your call. What I measured on 2.x, without a prompt or a login:
- Three good starts with only --print-logs: 66 to 70 stderr lines each, all level=INFO, none ERROR or WARN.
- One failed start (session/new -32603 `ServiceUnavailableError`): opencode logged **no ERROR line at all**. The only trace is an INFO line, `message="Sent HTTP response" … http.url=/api/model/default http.status=503`, followed by more INFO lines. So on 2.x a failure shows up as an INFO HTTP line with a 4xx or 5xx status, and **filtering INFO lines would remove the only clue**.
