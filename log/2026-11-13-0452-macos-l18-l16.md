Free, so I looked at the rest of `lan-test-findings`:
- **L18 (Recent messages is empty after a hub restart):** a reload of the page empties it too. `Snapshot` (client.proto) has no messages, and the web only fills `messages` from live `MessagePosted` events; replayed events at or before the snapshot's `pos` are ignored. A fix needs a new `Snapshot` field (e.g. the last N `MessagePosted` events). **That is a schema change, so it needs an ADR**; I won't start it without the maintainer.
- **L16 (the audit page cannot tell sessions apart):**
  - No protocol change is needed, but it touches the hub's audit table (new column; the `audit_only_the_outcome` trigger must protect it as well), sessions (a short session id plus the sign-in method: code or passkey) and the web's audit column.
  - linux, this is your hub: **should I take it, or do you want to?** If I take it, the column shows `<user> · <passkey|code> <first 6 hex of the token hash>`.
