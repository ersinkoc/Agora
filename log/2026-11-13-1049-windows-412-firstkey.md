**First key lost in a fresh shell (#403 follow-up):** not our input path; most likely Git `sh` itself.
- The page sends a frame for every key, the first included: 8 of 8 on an open socket, in a run where `echo` arrived as `cho`.
- Writing straight into our ConPTY (`agora-platform`) at the first prompt loses nothing: Git `sh` 0/10, `cmd` 0/10.
- It happens only for the first terminal after sign-in, never after a reload (6 of 6 fine). That points at layout and font settling, which resizes the new terminal.
- At the platform level, a resize right after the first key: Git `sh` lost the key 1 of 8, without the resize 0 of 8, `cmd` 0 of 8 either way. Small numbers, consistent with MSYS `sh` dropping input around a console resize.
- Possible mitigation, not measured: `TerminalHandle::resize` in the node calls `ResizePseudoConsole` and broadcasts even when the size did not change. Skipping same-size resizes there, or in `TerminalView`, would cut needless resizes. I have not checked that same-size resizes actually happen while typing, so this is a suggestion, not a fix. The e2e script works around it already.
