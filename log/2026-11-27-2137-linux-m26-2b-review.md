**1. should-fix, blocks the flip: the node never checks that the pipe server is the holder.**
- Where: `holder.rs` `open()` (~440); `holder_link.rs` `connect_with_version` (~1143) and `in_band` (1088); spec `holder-link.md:420`.
- The node trusts `holder_pid` and `holder_start` from `HelloOk`, which the server reports about itself.
- The pipe name is predictable and machine-global. When no holder runs, another local user can create the pipe first, claim any victim-user process in `HelloOk`, then answer `Attach` with `TerminalRef`s that guess the node's own handle values.
- Those guesses pass `import` if they are pipes, and the node later double-closes handles it holds for something else.
- Fix:
  - before `Attach`, compare `GetNamedPipeServerProcessId` with `holder_pid`;
  - check it through the `ProcessWatch`, and the user;
  - add a threat-model row (T47 covers only the holder admitting the node).

**2. nit: `import` (`conpty.rs:532`) cannot tell a fresh duplicate from a handle the node already holds.** `GetFileType` also says PIPE for sockets. Also require `GetNamedPipeInfo` to succeed on both. The stronger design, where the node pulls the handles with `PROCESS_DUP_HANDLE`, is only a note.

**3. nit: "no read outlives it" is not guaranteed (`conpty.rs:1093`, `1249-1258`).**
- `stop_reading` gives up after 2 s, and `Drop` joins the reader only if it has already finished.
- Fix: call `CancelSynchronousIo` on the reader thread as a fallback, or drop the 2 s limit.
- Also, `detach()` while the 64-chunk channel is full loses chunks the node already read.

**4. nit: `hold.rs:55`, the `with_terminal` `other => other.clone()` arm, can leak both duplicates** (it calls `delivered()` without the reference). Make that case an error.

**5. nit: spec deviation (`hold.rs` ~767).** A running agent whose `term.handle()` fails gets a plain `Terminal`(69), but the spec says 69 is for ended agents only. Refuse or skip that agent, or reword the spec.

**6. nit: `holder_link_ref_format.rs:93`.** The size check only runs on Windows. Say so in the doc comment.

**7. nit: `spawn_detached_unbound` repeats `winhold::start_holder`.** It also adds a `#[cfg(windows)]` block in `lib.rs` rather than `windows.rs`. That follows an existing pattern, but goes against the `<os>.rs` rule.
