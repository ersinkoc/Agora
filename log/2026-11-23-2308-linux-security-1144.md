# PR #1144: the node enforces the dynamic-stream allowlist (security)

Branch `claude/node-dynamic-stream-allowlist`, head 586da61b. The repo is public, so the PR body is neutral on purpose. The full detail is here.

## Defect (on main since 6aec8ce3, 2026-11-08)
- `agora-node::uplink_client`: a `CommandRequest` from the hub on a dynamic stream (≥ 3, kind 0) was decoded and passed to `relay_terminal`, which sent it with `request_on(stream, req)` to the control socket. It never went through `run_local_on`, so it skipped:
  - ADR-0020 `signed_commands` signatures;
  - ADR-0041 grants;
  - ADR-0059/0066 unsigned launch options and settings;
  - the `ControlAuth` refusal;
  - the #1133 registry signed-start gate.
- `control.rs` `handle_request` handled TerminalSubscribe and ChatSubscribe and passed every other command to `execute()`, whatever the stream.
- Only an honest hub refused (`agora-hub/src/server.rs` ~1320). So a compromised hub could make a node run any command on stream 3+.
- Shown on unfixed main by the new test, with `signed_commands = agent.start, agent.launch`:
  - `AgentStart` on a dynamic stream answered ok and the stub started;
  - `AgentStop` on a dynamic stream stopped the user's agent;
  - `ControlAuth` on a dynamic stream answered ok.
  An unsigned `AgentLaunch` there answered invalid_message on its own merits; it is still refused before the socket now.

## Fix
- Allowlist on a dynamic stream: `TerminalSubscribe`, `ChatSubscribe`, `PreviewConnect` (`control::opens_stream`), from protocol.md: terminal relay, the chat transcript stream, and ADR-0088 PreviewConnect.
  - The uplink answers anything else, and `command: None`, with `protocol.invalid_message {field: stream_id}` on stream 1, before the relay is registered. It never reaches the socket.
- Gap 3: on stream 1, `run_local_on` runs `grants.gate()` on every command, subscriptions included. The relay path did not. `relay_terminal` now takes the grants and gates first, so a policy listing `terminal.subscribe`, `chat.subscribe`, `terminal.*` or `*` holds on dynamic streams too.
  - `grants::subject()` has no subject for subscriptions, so only a `node` grant covers them, the same as on stream 1. I did not change that here.
  - Input and resize stay stream-1 commands, so they are fully checked.
- `control.rs`, defence in depth for local clients: after the auth check and before the idempotency claim, a dynamic stream takes only `opens_stream` commands, and a Terminal/ChatSubscribe on stream 1 is invalid.
  - Before, ChatSubscribe on stream 1 pumped kind 10/11 frames onto stream 1.
  - Every local caller I found (`agora terminal attach` in main.rs, the TUI and the web through the hub, all tests) sends only subscriptions on dynamic streams.
  - `ControlAuth` is still handled first on any stream locally, since it only authenticates that connection. The uplink refuses it on dynamic streams.
- PreviewConnect is allowed and still answers `protocol.capability_missing` from execute(), as the spec says.

## Tests (`crates/agora-node/tests/hub_streams.rs`, a fake ws hub against a real `Node::start` + `uplink_client::spawn`; all 3 failed on main first)
1. `signed_commands = agent.start, agent.launch`:
   - stream-1 AgentStart gives `approval.grant_required`;
   - on dynamic streams, AgentStart, unsigned AgentLaunch, AgentStop, ControlAuth and an empty request each give `protocol.invalid_message` and no frames on those streams;
   - the stub marker is absent and agent.list holds only the shell;
   - TerminalSubscribe answers ok with a kind 1 snapshot, ChatSubscribe answers ok with a kind 10 snapshot, and PreviewConnect gives capability_missing.
2. `signed_commands = terminal.subscribe, chat.subscribe`: both subscriptions on dynamic streams give `approval.grant_required` and no frames.
3. Control socket: AgentStart and AgentStop on a dynamic stream give invalid_message, ChatSubscribe on stream 1 gives invalid_message, ChatSubscribe on stream 5 answers ok, and the stub never runs.
