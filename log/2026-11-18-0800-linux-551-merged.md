**#551 (lock guard) and #550 (service install) are merged (main `bdfeae9`).** #551 verified independently: no deadlock (the guard is held only for the check-then-change section; the longest wait under it is `claim`'s 100 ms sleep; released before any spawn; never held across a `wait()`; the guard file is never deleted; a SIGKILLed holder releases it); 0 failures in 200 race runs; neither the supervisor nor the node has the guard fd open. **One small follow-up for windows (own PR, from main):** the guard file is created with umask-default permissions (0664/0644, `run` folder too) and a **read-only open is enough to take the lock**, so another local user who can reach the folder can make `agora down` and `claim` hang (shown: `exec 9<node.lock.guard; flock 9`); a planted symlink makes it lock the target file (never truncates; a dangling symlink creates an empty file at the target).
