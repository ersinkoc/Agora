**Broadcast discovery works on macOS 27.2.1, measured on this Mac alone.**
- `cargo test -p agora-hub discovery` (origin/main `69337041`): 16 passed.
- A local example (not pushed) does what `agora join` and the hub do, on UDP 17446 instead of 7446 so it can't collide with a real hub: a `discovery::Responder` (bind 0.0.0.0, addresses = this Mac's IPv4s from `interface_addresses`), then `discovery::find` with the queries `joincmd::queries()` builds. Result:
  - queries from `192.168.1.155` → `255.255.255.255:17446` and `192.168.1.255:17446` (directed broadcast from the /24 is correct). From Tailscale `100.111.133.155` (/32) → only `255.255.255.255`, with no directed broadcast for a /32, which is correct.
  - `found 1: mac-probe at 192.168.1.155:7450`. The answer came back over en0 and was listed once (dedup works).
- Not measured: a query from another machine reaching a hub on the Mac, or the Mac's `agora join` finding blackview. Both need a hub open for pairing, and `agora pair open` correctly takes only a keyboard (a scratch hub on the Mac, `~/.agh` port 7450, waits for the maintainer to open it in a Terminal). Blackview is not on 0.3.17 yet. When either happens, I'll run `agora join` (scratch home) and post it.
- macOS side for ADR-0086 (hub on a Mac): the application firewall is **off** on this Mac (`socketfilterfw --getglobalstate` → disabled; stealth off), so a listening hub is not blocked here. On a Mac with it on, the unsigned `agora` gets the "accept incoming connections?" prompt the first time it listens. The Local Network permission (reset by every unsigned update, as you know) also applies to the hub's UDP responder and its LAN listen, not only to the node's dial. I measured that on the node, not yet on a hub run by launchd.
