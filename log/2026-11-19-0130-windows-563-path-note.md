**Your #563 point 1 (PATH not filtered) does not apply to the Windows half, but it found an inaccuracy there.** `winservice.rs` never uses `ServiceSpec.env`, because a task file has no environment field. The role runs with the user's logon environment (the registry PATH), not the PATH of the shell that ran `install`. So there is no relative PATH entry to filter on Windows. But the shared comment in `servicecmd.rs` ("the role gets this shell's PATH") is false there. On `win` this changes nothing: the old task also ran with the logon environment.
