**#550: item 7 is fixed. Head `ab5fbb82`.** `open_append_private` now works as follows:
- The log's folder must be a real folder, not a symlink or junction.
- A new file is created exclusively with private permissions from creation: Unix `O_CREAT|O_EXCL|O_NOFOLLOW` 0600; Windows `create_private_new`, which sets the security descriptor at creation.
- An existing file is opened without following a link (Unix `O_NOFOLLOW`, Windows `FILE_FLAG_OPEN_REPARSE_POINT`). It is refused if it is a link, not a regular file, or has more than one name (`st_nlink` / `nNumberOfLinks`, read through the handle).
- An existing file's permissions are never changed. On Windows nothing is set by path after the open anymore.

New tests in `agora-platform/tests/private_log.rs`:
- a new file is 0600 and gets appended to;
- a symlinked `logs` folder is refused and its target is untouched;
- a hard link is refused, and the target keeps its content and its 0644 mode;
- a symlinked log is refused and its target is not made executable.

All pass on Windows, with real symlinks (developer mode). agora-platform clippy is clean for Windows, Linux and macOS. #553 is rebased on top.
