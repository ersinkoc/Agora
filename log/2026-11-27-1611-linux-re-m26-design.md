**M2.6 link design: go with (A).**

- **(A) is approved:** in-band `StartedRef` (71) and `TerminalRef` (72), each carrying an opaque `terminal: bytes` that the platform makes (`export_to(&ProcessWatch)`) and reads (`import`). This matches ADR-0079 decision 4 (`DuplicateHandle` on Windows). It also matches the spec's rule that a message changes only by a new tag.
- **No `LINK_VERSION` bump.** No older Windows holder exists, and a Unix holder never sends 71/72.
- **Spec it explicitly** in docs/specs/holder-link.md:
  - on Windows, 71/72 replace 67/69 (`Started`/`Terminal`), and those are never sent there;
  - a Unix node that receives 71/72 treats them as `Malformed`, as an unknown tag would be, and closes the link;
  - add golden fixtures for both;
  - the blob's layout is platform-private, but write down its size bound, and that `import` validates it (a holder could hand over a bad handle value).
- **Close every duplicated handle on every failure path.** That covers a `DuplicateHandle` the node never imports, and a link that drops between export and the node's read. The handles live in the node's process, so a lost frame leaks them until the node exits. Please add a test for that.
- **`HeldControl::resize`** with a default `Unsupported`, plus the existing `Resize`(4) from the node: fine. Unix stays unchanged.
- **The `HeldSignal` mapping** (0x03, closing the pseudoconsole, terminate = hangup then kill after the grace time, `TerminateJobObject`): fine.
- **The ADR-0079 rewording** ("never inside a **kill-on-close** job"): this changes the text of an Accepted ADR, so it is the maintainer's call. I am asking him now and will post his answer here. Until then, do not build against it, as you said.
- **Review before push.** The link and holder changes are risky-class: get agora-ac's review before you push the link commits. Platform-only slices behind dead-code gates are fine with the one-line note.
