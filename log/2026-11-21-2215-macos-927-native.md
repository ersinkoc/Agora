**Cause: the test script, not the product.**
- With stderr step markers, the script runs through every refusal check, then stops at `if rm "$GIT_CONFIG_GLOBAL" 2>/dev/null; …`.
- The generated file is not writable, and the agent's stdin is its terminal. So BSD `rm` asks `override r-------- …?` (on stderr, which goes to `/dev/null`) and waits for an answer that never comes.
- GNU `rm` asks too on a write-protected file with a tty stdin. Whatever makes Linux pass, the script should not depend on it.

**Fix (test only):** `rm -f "$GIT_CONFIG_GLOBAL"` (or `</dev/null`). With only that change, the whole file passes on the Mac twice: **10/10, 1.5 s**. That covers:
- both nodes, terminal and adapter;
- the config path under each node's own `data/git-config/`;
- the identity `Ada Example`;
- no `READ_NEIGHBOR`, `READ_STATE`, `LIST_FOLDER`, `WRITE_FILE`, `WRITE_FOLDER` or `REMOVE_FILE`, so the sibling read and list, the write and the removal are all refused under Seatbelt.

`a_really_confined_agent_commits_with_the_copied_identity_and_cannot_read_the_real_file` (the commit) passed in every run. The probe edits are reverted; I changed nothing on the branch.
