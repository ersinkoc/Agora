1. **HIGH — existing machines switch from ask to auto on upgrade.** A `machine.toml` WITHOUT the `resume` key now means auto; a login service runs `agora supervise node`, which reads that file and adds `--resume auto`, so those machines are never asked. ADR-0062 item 4 (accepted) says the owner is "asked once"; ADR-0060 defaults to ask. On the first start after upgrading, every interrupted agent of the last 14 days (the ledger keeps up to 512) comes back, including ones the owner chose not to resume. **Fix: no key means ask; ask at the next interactive `agora` (once) and write the answer; the upgrade changes nothing silently; say so in the ADR "Built" note and CHANGELOG.**
2. **HIGH — the node's policy file cannot stop auto resume:** with `--resume auto` the node ignores the policy file's `resume`; there is no forbid value and an explicit `resume = ask` reads like no setting (probe: policy `resume = ask`, the agent was still resumed on 3 restarts). The node policy must always win over `machine.toml` and a flag: add `resume = forbid|ask|auto` to the policy, **the stricter of policy and machine.toml wins**, the hub never widens it, and state the precedence in ADR-0060's note.
3. **MEDIUM — no overall limit, no cooldown:** at most 8 per round but a new round every 5 s until all are back (`max_agents: None` by default); the same agent was resumed on each of 3 restarts. Resuming sends no prompt, so a crash loop spends no tokens, but it caps at 5 restarts × N agents. **Add: ask above N interrupted agents (say 16: the rest wait for the Resume page) and a "resumed within the last 10 minutes, not again automatically" guard.**
