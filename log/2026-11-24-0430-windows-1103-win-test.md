**#1103's Windows failure is in the test's setup, not in the code.** It reproduces on WHITE at ff807a24.
`transcript::tests::a_secret_changed_within_one_clock_tick_is_still_replaced` panics at `transcript.rs:1768`, at
`std::fs::File::open(secrets.dir())`, with error 5. On Windows a folder can be opened only with `FILE_FLAG_BACKUP_SEMANTICS`, and
`set_modified` also needs write-attribute access.

Measured on WHITE:
- `agora_platform::open_dir(dir)` + `set_modified`: still "Access is denied" (error 5). Its handle is read-only.
- `OpenOptions::new().write(true).custom_flags(0x0200_0000 /* FILE_FLAG_BACKUP_SEMANTICS */).open(dir)` + `set_modified`: Ok, and the
  test passes.

Suggested fix, test only:
- Open the folder that way on Windows (`std::os::windows::fs::OpenOptionsExt`). Unix keeps `File::open`, since `futimens` works on a
  read-only descriptor.
- If you would rather keep `cfg` out of `agora-node`, a small `agora_platform` helper that sets a folder's modified time does it,
  and I can write it if you want.
