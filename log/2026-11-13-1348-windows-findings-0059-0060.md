**0059/0060 measurements on Windows** (main build; agy 1.5.6, opencode 2.2.6, Claude Code 2.1.323, Codex 0.169.0; existing logins; three cheap prompts in all).

**0059: skip flags**
- **agy `acp --dangerously-skip-permissions`:**
  - Accepted, but invisible in ACP: `session/new` gives the same modes and `currentModeId: "default"` with or without it, so the window cannot tell from the session; only the signed launch option can drive the badge.
  - **On this machine it changes nothing**, because the user's agy CLI settings already have `toolPermission: "always-proceed"` and trust the whole profile folder (`~\.gemini\antigravity-cli\settings.json`; the ACP settings file holds only auth).
  - A file-writing prompt ran without any permission request in "Default" mode, with and without the flag.
  - **Consequence:** an agent's *own* config can already skip every question while Agora shows "Default" and no "does not ask" badge. The badge means "Agora started it with a skip option", not "this agent never asks". Please word it that way, or document it; Agora cannot read every tool's config.
- **opencode 2.2.6:** `opencode acp --auto` is **refused** ("Unrecognized flag: --auto in command opencode acp") and exits. `--auto` exists only for the TUI (`opencode [dir] --auto`). So opencode-acp has no skip launch flag on 2.x.
- **Claude Code 2.1.323:** this user's Claude also runs with **"auto mode on"** from their own settings (status line), the same pattern as agy.

**0060: native session ids under ConPTY.** Both can be read without scraping, from files the usage reader (ADR-0042) already matches to the agent by `cwd`:
- **Codex 0.169.0:** `~\.codex\sessions\YYYY\MM\DD\rollout-<time>-<uuid>.jsonl`. The `<uuid>` (also the first line's `payload.id`) is the session id, and `cwd` is the agent's folder. The file is written at the first prompt.
- **Claude Code 2.1.323:** `~\.claude\projects\<folder with \ and : turned into ->\<uuid>.jsonl`. `sessionId` is on every line and `cwd` is the agent's folder. Nothing is written before the first prompt.
- So: take the session id from the usage file the node already tied to the agent (stem or `sessionId`/`payload.id`). An agent that never got a prompt has no id, so its interrupted entry offers "Start again" (as the ADR says).
