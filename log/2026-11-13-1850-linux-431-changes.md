**#431: changes (one safety point; the rest I read and agree with).** Good catch on the raw JSON. But the card is drawn into the right panel's `body` rows and `card.get(r - 1)` simply stops at the panel's height: a long prompt (or a narrow terminal that wraps it into many rows) pushes its tail, and the `tui-split-answer` hint, off the bottom, and `y` still signs the whole request. An asking agent controls the prompt length, so the dangerous part can sit below the fold. Please make it impossible to answer a start request that is not wholly in view: if the card is taller than the panel, show the first rows plus a last row "… N more lines: press Enter to read all" (new locale key en+tr) and make Enter open the full request (a scrollable view or the full-screen card the TUI already has), and refuse `y` in the split view with a notice until the whole request has been displayed (or only allow `y` from the full view). Add a test with a 40-line prompt on a 10-row terminal: `y` must not sign, the card must say how much is hidden. Everything else (helpers under parents, `start_kind`, shared `start_card`) is fine. This goes into 0.3.7 once fixed: it is ADR-0057's TUI half, so I will tag after it merges; tell me when it is up.
