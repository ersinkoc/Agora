# Phase 6 backlog (extensibility and global readiness)

Started with the terminal client (ADR-0043). Other Phase 6 items: the install step of the adapter registry is ADR-0044 (accepted; P6-07); RTL has only its foundation (P6-06).

| Task | State | Notes |
| --- | --- | --- |
| P6-01 TUI slice 1: read-only console | done | `agora tui [--hub HOST:PORT --ca FILE --code CODE] [--hub-dir DIR]`: signs in with a one-time code (made by itself on the hub's own machine), follows the hub's snapshot and draws machines, agents grouped by project with their state and the attention list; `NO_COLOR` spells states out without escape codes; text in `locales/{en,tr}/tui.ftl`; pure render with unit tests, a real hub and node in `crates/agora/tests/hub_dial.rs`. It refreshes by asking the hub for a new snapshot (at most every 500 ms after something changed); applying single events is later work |
| P6-02 TUI slice 2: approvals | done | `y`/`n` answers the first waiting request with this terminal's ES256 key (`<AGORA_HOME>/tui-device.p8`, owner-only file, id `tui-<hex>`; `agora-tui::device`), sent as `approval_resolve` through the hub; a machine that does not trust the key answers `approval.signature_invalid` and the console shows the `agora node trust ID KEY` line to run there; raw-mode key reading (`agora-platform::RawMode`), no keys when stdin is not a terminal; tested end to end with a real hub, node and adapter agent in `hub_dial.rs`, and the signed bytes against `agora-node`'s own function. Signed grants (ADR-0041): when a machine refuses with `approval.grant_required` (start, stop, typing a request in the chat), the console asks and, on `y`, signs a grant for one hour with this device (scope `agent:<id>` or `project:<id>` as in the web client) and repeats the action; tested through a real policy in `hub_dial.rs`. Typing into an opened terminal is not covered: its keystrokes are fire-and-forget, so a refusal would be silent |
| P6-03 TUI slice 3: terminal | done | `Tab` points at an agent that has a terminal, `Enter` opens it through the hub's relay (ADR-0029), keys go to it as routed `terminal.input`, `Ctrl-]` comes back; the screen repaint and output are written as the machine sent them; the size is sent when it opens and again whenever the window's size changes (checked every 50 ms while the terminal is open); a project shows under its folder name; tried in a real pseudo-terminal against a real hub and node (Tab, Enter, typing, Ctrl-], q) and tested through the hub in `hub_dial.rs` |
| P6-04 TUI slice 4: chat, start, stop, usage line | done | every running agent can be picked with `Tab`; `Enter` opens its terminal or, for an agent without one, its conversation (ADR-0038: entries as plain text, with control characters and bidi overrides dropped, last lines that fit, a line to type the next request on); `x` stops the picked agent; the header adds up the tokens agents used. `s` lists the agents the picked agent's machine can start (or the first online machine with a project) and starts the chosen one in the same project. The header also shows the hub's cost estimate (`usage.report`, ADR-0033) when it has prices |
| P6-05 `agora update` (ADR-0019) | done (the program; not a live handoff) | `agora update [--check] [--version X] [--release-url URL] [--release-key FILE] [--unsigned]`: finds the newest release through `releases/latest`, downloads this platform's binary, checks its SHA-256 against the published `.sha256` and its signature (`ssh-keygen -Y verify`) against the release key pinned in `<AGORA_HOME>/release-key`, then replaces the program (`agora-platform::replace_executable`; Windows moves the old one aside). Nothing changes on any refusal. Running agents are not touched; the new version runs when the node is started again and agents resume through their own session ids, which is the ADR's first-release behaviour. Live handoff of terminals to the new process, the hub distributing binaries and an approval step before updating (ADR-0019 lines 2 and 3) are not done. Tested against a loopback release server with real signatures in `crates/agora/tests/update.rs` (Unix only; the Windows rename path is unexercised) |
| P6-06 RTL foundation | partly done | the page's `dir` follows the language (`apps/web/src/i18n.ts` `directionOf`: ar, he, fa, ur, ps, sd, yi, dv, ku), set with `lang` on `<html>`; tested. No right-to-left translation ships yet (a new locale needs a native reader, like `locales/tr`), and the layout still uses physical left/right Tailwind classes in places: before the first RTL locale, move them to logical ones (`ms-`, `me-`, `ps-`, `pe-`, `start-`, `end-`) and check both directions in the screenshot run |
| P6-07 `agora adapter install\|list\|remove` (ADR-0044) | done (install, list, remove) | `agora adapter install NAME [--registry URL] [--root-key FILE] [--yes]`: fetches `index.json`, checks it against the root key pinned in `<AGORA_HOME>/registry-root-key` (expiry, rollback against `registry-version`), downloads `packages/<name>-<version>.tar` and `.sig`, verifies hash and publisher signature (`agora-adapters::registry`), reads the tar with `agora-adapters::package` (regular files only, safe relative paths, at most 64 files and 64 MiB), shows publisher, key, checksum and the command it will run and asks once. `--yes` skips the question only for a publisher already in `<AGORA_HOME>/publishers` (stricter than the ADR's "first-party": the project has no first-party registry yet). Files land in `<AGORA_HOME>/adapters/<name>/<version>/` (owner-only), older versions are removed, and the manifest goes to `<manifests dir>/<name>.toml` with `./` command entries pointing into that folder; a manifest of the same name that was not installed this way is never overwritten. Nothing runs at install. The address must be https or loopback. `list` marks packages whose publisher the stored index revokes. The node refuses to start an agent whose adapter program lives in an installed package of a publisher the stored index revokes (`agent.publisher_revoked`, before any worktree is made; `agora-adapters::package::revoked_publisher_of`, test `crates/agora-node/tests/revoked_adapter.rs`). Not done: the hub's `registry-url` is read but the hub does not serve or mirror a registry, and `agora adapter update`. Tested with real Ed25519 signatures against a loopback registry in `crates/agora/tests/adapter_install.rs` and unit tests in `package.rs` |
