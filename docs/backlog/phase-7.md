# Phase 7 backlog (scale out)

Started with the Windows node (ADR-0045). The only machine used for development is Linux: Windows code is compiled for `x86_64-pc-windows-gnu` and linted locally, and everything that runs is proved by the `windows-latest` CI job.

| Task | State | Notes |
| --- | --- | --- |
| P7-01 Windows node W1: named-pipe control channel | done (W1) | `crates/agora-platform/src/windows.rs`: `local_listen`/`local_connect`/`LocalStream` over a named pipe `\\.\pipe\agora-<file name>-<hash of the path>`, owner-only security descriptor (`D:P(A;;GA;;;OW)(A;;GA;;;SY)`), remote clients rejected, first instance exclusive (a second listener gets `AddrInUse`), overlapped I/O so a waiting read never blocks a write from another thread, read timeouts and `shutdown` by cancelling the pending read. `LOCAL_SOCKETS_SUPPORTED` is true on Windows. A marker file stays at the socket path while a listener serves, so callers see that a node is up as with a Unix socket file. Three unit tests in `windows.rs` run on `windows-latest` (talk both ways and refuse a second listener; would-block, read timeout and shutdown with a concurrent write; end of stream when the peer closes); the control, ACP and hub tests that need only a socket now run there too, the ones that start a terminal agent stay gated on `PTY_SUPPORTED` |
| P7-02 W2: ConPTY terminals and job objects | done (W2) | `crates/agora-platform/src/conpty.rs`: `spawn` starts the child attached to a pseudo-console (two anonymous pipes, `CreatePseudoConsole`, the pseudo-console process attribute), puts it in a job object that kills the tree when closed (and carries the memory and CPU limits), reads output on a thread into the same bounded channel, closes the console when the child ends so the output channel ends, resizes with `ResizePseudoConsole`. `foreground_pid` is the child itself (no foreground group on Windows). The child is started with `STARTF_USESTDHANDLES` and no handles: without it a parent whose own streams are redirected (a test harness, a service) makes the child write there instead of to the console (found on CI: `cmd /c echo` ended with its exit code but printed nothing). Four tests in `conpty.rs` run on `windows-latest` (argument quoting, output and exit code with the output channel ending, input/resize/kill, the whole tree dying with its terminal). `PTY_SUPPORTED` stays false until W4 has the node tests running |
| P7-03 W3: process view (tree, name, stats; no cwd) | done (W3) | `crates/agora-platform/src/winproc.rs`: `process_name` (image file name without `.exe`, `QueryFullProcessImageNameW`), `process_stats` (`GetProcessTimes`, `GetProcessMemoryInfo` working set), `process_children`/`process_tree` (toolhelp snapshot). `process_cwd` stays unsupported (the PEB is undocumented). A program started through a `.cmd` shim (most npm-installed agents) shows as the interpreter (`node`), so manifest `names` do not match it: detection there relies on screen rules and hooks. Two tests in `winproc.rs` run on `windows-latest` |
| P7-04 W4: supervisor, terminal and node integration tests on `windows-latest` | done (W4) | `PTY_SUPPORTED` is true on Windows; `terminal.rs` and `supervisor.rs` lost their `cfg(unix)`; the control, supervisor, terminal, CLI (`start`, `attach`, `stop` in a real pseudo-terminal), ACP, hub and usage-file tests run there against real ConPTY terminals and named pipes. Also added for this: raw console mode (`ENABLE_VIRTUAL_TERMINAL_INPUT`, no line editing or echo) and the window size on Windows, so `agora terminal attach` and `agora tui` can run there. One test stays off on Windows by design: the usage test whose "agent" is a POSIX shell writing its own `$PWD` (Git's `sh` reports `/d/a/...`, which is not the worktree's native path). | P7-09 Team mode (ADR-0049) | in progress | T1a done: `users` table (schema 5), roles `owner`/`member`/`viewer`, sessions carry their person (a session with none is the owner's, so a one-person hub is unchanged), `agora hub user add NAME [--role] | list | role ID ROLE | remove ID | login ID`; the hub asks for the role on every command (a demotion or removal applies to the open connection at once) and stops a viewer's commands that change anything with `auth.forbidden` (`action` = the command's schema name), before any node hears of them (`agora_hub::users::viewer_may` lists what a viewer may still do; a new command is refused to viewers until listed). No schema or error-code change. T2a done: an append-only `audit` table (schema 6; triggers refuse deletes and any edit but the one-time outcome of a `sent` row) with who (person id, `owner` for the owner), what (the command's schema name, `sign_in`, `user.add|role|remove`), where (node) and the outcome (`ok` or the error code; `sent` while a command has no answer); every routed command is recorded when it is sent and finished when the node answers, a refused one at once, sign-ins and changes to the team too; `agora hub audit export [--since MS] [--who ID]` writes JSON lines. Terminal bytes and message bodies are not in it. T1b done: a member or viewer sees and works in only the projects they were granted (`agora hub user grant|revoke ID NODE/PROJECT`, schema 7; an owner needs none; a member with no grant sees nothing). `agora_hub::scope::Scope` follows the event stream a client gets, remembers which project each agent, worktree, terminal and approval belongs to, and decides for every event and every command whether it is theirs; a restricted client always gets a snapshot cut to its projects (whatever position it asks to replay from) and then only its own events, and the hub refuses (`auth.forbidden`) any command that does not name something in a granted project, including everything about a whole machine (`ProjectList`, `AgentList`, `NodePolicyGet`, `TerminalOpen`, grants, usage). A machine shows up only if it hosts a granted project. A change of role or grants ends the open connection and the client reconnects into what it may now see. Hidden on purpose: terminals that belong to no agent, the shared board of a project that spans machines (tasks), messages from agents the person cannot see. Tested with plain event sequences in `scope.rs` and end to end in `crates/agora-hub/tests/server.rs`. T2b done: the owner reads the trail in the web app (`#/audit`, "Activity" in the command palette): `GET /api/audit?since=&who=&limit=` with the session token, owner only (401 without a live session, 403 for a member or viewer, 400 for a query it does not understand), newest first, filterable by person; actions are named in words from `locales/{en,tr}/web.ftl` (an action this build has no words for shows as the hub named it). Screenshots in `docs/screenshots/audit-*.png`. T1c done (node side): `device.<id>.projects = a, b` in the node's `policy` (`agora_node::limits::DeviceLimits`): a limited trusted device can sign grants only scoped `project:X` or `agent:A` of its projects (never `node`; `auth.forbidden` `grant.create`) and can answer approvals only for agents of its projects (`auth.forbidden` `approval.resolve`, nothing consumed); an unnamed device is limited by nothing; a named one with no projects acts in none. No schema change. Not done: approval decisions as their own rows (they are `ApprovalResolve` commands today), the hub sending the member's own device with each command so the node can limit commands outside `signed_commands`, devices owned by a user, Postgres (T3), the shared board for members |
