# Phase 7 backlog (scale out)

Started with the Windows node (ADR-0045). The only machine used for development is Linux: Windows code is compiled for `x86_64-pc-windows-gnu` and linted locally, and everything that runs is proved by the `windows-latest` CI job.

| Task | State | Notes |
| --- | --- | --- |
| P7-01 Windows node W1: named-pipe control channel | done (W1) | `crates/agora-platform/src/windows.rs`: `local_listen`/`local_connect`/`LocalStream` over a named pipe `\\.\pipe\agora-<file name>-<hash of the path>`, owner-only security descriptor (`D:P(A;;GA;;;OW)(A;;GA;;;SY)`), remote clients rejected, first instance exclusive (a second listener gets `AddrInUse`), overlapped I/O so a waiting read never blocks a write from another thread, read timeouts and `shutdown` by cancelling the pending read. `LOCAL_SOCKETS_SUPPORTED` is true on Windows. A marker file stays at the socket path while a listener serves, so callers see that a node is up as with a Unix socket file. Three unit tests in `windows.rs` run on `windows-latest` (talk both ways and refuse a second listener; would-block, read timeout and shutdown with a concurrent write; end of stream when the peer closes); the control, ACP and hub tests that need only a socket now run there too, the ones that start a terminal agent stay gated on `PTY_SUPPORTED` |
| P7-02 W2: ConPTY terminals and job objects | done (W2) | `crates/agora-platform/src/conpty.rs`: `spawn` starts the child attached to a pseudo-console (two anonymous pipes, `CreatePseudoConsole`, the pseudo-console process attribute), puts it in a job object that kills the tree when closed (and carries the memory and CPU limits), reads output on a thread into the same bounded channel, closes the console when the child ends so the output channel ends, resizes with `ResizePseudoConsole`. `foreground_pid` is the child itself (no foreground group on Windows). The child is started with `STARTF_USESTDHANDLES` and no handles: without it a parent whose own streams are redirected (a test harness, a service) makes the child write there instead of to the console (found on CI: `cmd /c echo` ended with its exit code but printed nothing). Four tests in `conpty.rs` run on `windows-latest` (argument quoting, output and exit code with the output channel ending, input/resize/kill, the whole tree dying with its terminal). `PTY_SUPPORTED` stays false until W4 has the node tests running |
| P7-03 W3: process view (tree, name, stats; no cwd) | in progress | `crates/agora-platform/src/winproc.rs`: `process_name` (image file name without `.exe`, `QueryFullProcessImageNameW`), `process_stats` (`GetProcessTimes`, `GetProcessMemoryInfo` working set), `process_children`/`process_tree` (toolhelp snapshot). `process_cwd` stays unsupported (the PEB is undocumented). A program started through a `.cmd` shim (most npm-installed agents) shows as the interpreter (`node`), so manifest `names` do not match it: detection there relies on screen rules and hooks. Two tests in `winproc.rs` run on `windows-latest` |
