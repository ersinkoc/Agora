# 0007. Localization with Fluent; codes not text in APIs
Status: Accepted
Date: 2026-11-06

## Context
The product is global. Plural, case, and gender rules differ across languages; retrofitting localization is
expensive. A hub may serve clients in different locales.

## Decision
- All user-facing text is in Project Fluent files under `locales/`; English is the source locale.
- APIs and protocol errors return `{ code, params }`; clients localize.
- Times stored in UTC; formatting happens in the client.

## Consequences
- No string literals for user-facing text in Rust or TypeScript UI code; lint for it.
- Error codes are part of the public protocol and follow ADR-0006 rules.
