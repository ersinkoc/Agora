# 0033. `usage.report`: tokens and estimated cost for clients
Status: Accepted
Date: 2026-11-08
Accepted: 2026-11-08 (maintainer's explicit approval in chat)

## Context
The hub has the pieces of cost (ADR-0021): token usage per agent in its view, a price catalog parser with overrides, and exact
micro-USD arithmetic (`agora-hub::usage`). Clients get tokens but no money: the web window shows "tokens used" in Focus and has no
cost view. Prices must not be duplicated in the client (two implementations drift, and the catalog and overrides live on the
hub). There is no message a client can use to ask the hub for them, and the catalog is not loaded by `hub run` at all yet.

## Decision
**A client command answered by the hub itself.** `UsageReport` is a new `CommandRequest` body (`usage_report = 17`, empty message)
with a new `CommandOk` body `UsageReportResult` (`usage_report = 14`). It has no `target_node`: the hub answers it from its own
view and catalog and never routes it to a node. (A request that carries `target_node` is routed as today; a hub-answered body
that names a node is refused with `command.invalid`.) It needs the same client credentials as any command.

```proto
message UsageReport {}
message UsageReportResult {
  repeated AgentUsage agents = 1;
  // Sum over agents with a price, micro-USD (1 USD = 1_000_000). Agents without a price add nothing.
  uint64 total_micro_usd = 2;
  // When the price table was last refreshed, ms since the epoch; 0 for the bundled snapshot.
  uint64 prices_at_ms = 3;
}
message AgentUsage {
  string agent_id = 1;          // the hub-wide key <node>/<agent>
  string model = 2;             // as reported; empty when never reported
  uint64 input_tokens = 3;
  uint64 output_tokens = 4;
  // Present only when a price is known (catalog or override). Never a guess: absent means "no estimate".
  optional uint64 micro_usd = 5;
}
```

Rules, from the design doc: an agent-reported cost wins over the estimate (reporting one needs a later, separate event field and is
not part of this ADR, so today every number is an estimate and the client says "estimated"); a model with no price has no
estimate; an override beats the catalog.

**Where prices come from.** The hub loads, in order: `<hub dir>/prices.json` (overrides, `{ "<model>": {input, output, cache_read,
cache_write} }` in USD per million tokens), then the catalog. The catalog is a trimmed snapshot of models.dev embedded in each release
(generated by `scripts/update-prices.sh` from `https://models.dev/api.json`, only the fields the hub reads, attribution in
`THIRD_PARTY.md`), optionally refreshed by `agora hub prices update`, an explicit command that fetches the live catalog over https
(the delivery client from the notification work, `agora-hub::deliver`, gains a GET) and stores it in the hub dir. There is no
automatic background fetch in this ADR: a hub that never talks to the internet stays that way unless the owner asks.

**Model ids.** A reported model id is looked up as given, then as `<provider>/<id>` for the manifest's declared provider when the
node reports one. Mapping tables stay the manifest's job (ADR-0021); an unmapped model shows tokens without cost.

**Scope.** Per-agent figures only; the client sums per project or machine from the same list. Subscription quotas, budgets and
alerts (`BudgetThreshold` already exists as a notification trigger) are separate decisions.

## Consequences
- Two new messages and one field in each oneof, golden fixtures for the new messages; additive, no existing meaning changes.
- The hub gains a catalog loader, the embedded snapshot (a few hundred KB trimmed) and one hub-answered command path in the
  client conversation; `agora-hub::usage` is used as written.
- The web window gets a cost line in Focus and a "spent" figure per machine and project, shown as an estimate with the prices' date.
- A stale snapshot gives stale numbers; the window shows the price date so that is visible, and `hub prices update` fixes it.

## Alternatives considered
- Send the price table to the client and compute there: duplicates the arithmetic and exposes private override prices to every
  client. Rejected.
- A JSON `GET /api/usage` beside the WebSocket: avoids a schema change but puts client data outside the schema-first protocol
  (ADR-0006) and gives it a second auth path. Rejected.
- Put cost into `View` snapshots: bloats every snapshot and every reconnect for a figure only one screen reads. Rejected.
