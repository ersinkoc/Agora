# Error codes

Errors are `{ code, params }`. `code` is a stable, dotted, lowercase string. `params` is a flat map of strings
and numbers used by clients to render localized messages (`locales/<lang>/errors.ftl`, key = code with dots
replaced by dashes). Codes are part of the public protocol: never rename or reuse one.

The terminal client's remove action preserves the hub's error parameters and renders its refusal from `errors.ftl` in the
selected language, including `agent.running` and `auth.forbidden`. Unknown codes remain visible as a fallback; a lost connection
or a local response timeout has a localized retry message.

### Command-line codes (ADR-0067 rung 3)

Printed by `agora remote` and `agora hub run` as `Error CODE: sentence`; never sent over the protocol and not in the table above, so they are not in `ErrorCode`. The sentences are in `locales/<lang>/cli.ftl` (`remote-<code>`).

- `remote.password_required` (params: —): ADR-0067 rung 3: **machine-local, never sent.** A way in from outside this machine was asked for (`agora remote tailscale`, a hub on a public address) and no screen password is set; nothing was changed. The sentence names `agora password set`
- `remote.password_in_use` (params: —): ADR-0067 rung 3: **machine-local, never sent.** `agora password clear` while a tailnet name, a serve rule or a public listen is on; the password stays
- `remote.tailscale_missing`, `remote.tailscale_logged_out`, `remote.tailscale_timeout` (params: —): ADR-0067 rung 3: **machine-local, never sent.** There is no `tailscale` command, this machine is not signed in to a tailnet, or the command did not answer in time
- `remote.tailscale_unreadable` (params: `reason`): ADR-0067 rung 3: **machine-local, never sent.** The answer could not be used; `reason` is `failed`, `too_big`, `garbage`, `no_name` or `bad_name` (a machine name that is not a plain `.ts.net` name, refused whole)
- `remote.serve_port_in_use` (params: `port`): ADR-0067 rung 3: **machine-local, never sent.** `tailscale serve` already serves something on that HTTPS port that Agora did not add; it is left alone
- `remote.proxy_header_invalid` (params: `header`): ADR-0067 rung 4: **machine-local, never sent.** `agora remote proxy --trust-header` named a header that is not a plain header name, or one the hub itself reads (`Host`, `Origin`, `Cookie`, ...); nothing was changed
- `remote.proxy_host_invalid` (params: `host`): ADR-0067 rung 4: **machine-local, never sent.** `agora remote proxy --host` named something that is not a plain public host name (an address, a wildcard, a port, `localhost`, a single label), or more than four; nothing was changed
- `remote.proxy_addr_invalid` (params: `addr`): ADR-0067 rung 4: **machine-local, never sent.** `--proxy-addr` is not an IP address, or more than four were given; nothing was changed
- `proxy.host_not_allowed`, `proxy.origin_not_allowed` (params: none): ADR-0067 rung 4: **HTTP only, never a protocol error.** While a trusted proxy is on, a request from the proxy (loopback or a listed address) whose `Host` is missing, repeated or not one of the configured names or a loopback name is answered `421` with the JSON body `{"error":"proxy.host_not_allowed"}`; one whose `Origin` names another host (or is `null`) is answered `403` with `{"error":"proxy.origin_not_allowed"}`. A WebSocket upgrade is answered the same way before it is accepted. The window has no sentence for them: a browser that reaches them is on the wrong address
